6.1.2.1 Species

cloud2trees does not currently include functionality to attach species to it’s tree list. there are a few paths forward for performing species-specific workflows with the cloud2trees tree list:

  1. use the FIA forest type group attached to the tree list via cloud2trees::cloud2trees(..., estimate_tree_type = T) or cloud2trees::trees_type(). since this process currently only attributes trees with a forest type group, we would need to manually map these groups to a specific species, for example, by selecting the main species for a given type.
  2. use the regional_dbh_height_model_training_data.csv file written to the point cloud processing directory when we execute cloud2trees::cloud2trees(..., estimate_tree_dbh = T) or cloud2trees::trees_dbh() to proportionally allocate tree species to the tree list randomly. For example, if there are 66% PIPO and 34% PSME in the regional_dbh_height_model_training_data.csv data, then we could randomly assign 66% of the cloud2trees tree list as PIPO and 34% as PSME
  3. use the regional_dbh_height_model_training_data.csv file written to the point cloud processing directory when we execute cloud2trees::cloud2trees(..., estimate_tree_dbh = T) or cloud2trees::trees_dbh() to build a species classification model based on height that would inherently account for the proportional distribution of different species. For example, using Softmax regression or a random forest classifier and then use that model to predict the tree species for our cloud2trees list

6.2 Predict Species

let’s demo option (3) to predict tree-level species using the TreeMap imputed FIA plot tree list to build a species classification model based on height and tree location to attach tree species to our tree list. such a model would inherently account for the proportional distribution of different species. We’ll try using Softmax regression with a model trained on the FIA tree list data to predict the tree species for our cloud2trees list.

For the Softmax regression model the categorical (i.e. nominal) tree species will be our dependent variable and the most simple model will use tree height and tree location (X and Y coordinates) as independent variables. The training FIA tree list data (identified from the TreeMap imputed plots of the area of interest) includes tree height and we’ll use the centroid of the TreeMap 30m raster cell to represent the individual tree X and Y location (i.e. each tree within the same cell will have the same coordinate). Considering the combined tree height and spatial location via a full interaction model (i.e. height*x*y) allows the model to capture how the species-height relationship varies across space.

An alternative model specification would be to use a hierarchical model grouped by imputed FIA plot identifier that allows the intercept and the slope of height to vary by plot. This model form would inherently capture spatial clustering without needing explicit X and Y coordinates in the model while also allowing the use of model weights to handle redundant TreeMap imputed plots. However, hierarchical models in brms can be computationally expensive because the model has to estimate a separate coefficients for every species. Thus, we’ll start with the interaction model (height*x*y) and treat space as a smooth surface since interpretation of the model coefficients is not really needed for our purposes, just the predictions.

if we are going to treat the FIA measured trees as individual observations to use for training data without using the imputed plot ID from TreeMap and weight by the number of times that specific id is repeated in the area of interest, then we need to get a tree list with the trees replicated based on the number of times the plot id is replicated. in addition, the TreeMap data product is a raster of imputed plots for a given area at 30m resolution and we should not assume that the tree list of that “guessed” plot represent the actual trees present at that location with complete accuracy. Instead, we expect the TreeMap imputed plots to be more accurate as we look over a broader area with accuracy decreasing at smaller scales. That is, when we consider the tree composition of an entire forest stand we expect TreeMap to generally get the main species and forest type correct but for each 30m raster cell (i.e. the plot location that we get the X and Y coordinates for the tree list used for training from) we expect it to be less accurate with a cell potentially being a completely incorrect representation of the actual ground setting. As such, we we’ll weight the individual tree records based on the stability of the imputed plot id’s looking over a window surrounding the focal cell. Specifically, we’ll calculate the proportion of surrounding cells (5x5) that share the same imputed plot id as the focal cell and use this weight as a measure of TreeMap’s predicted stability to place less weight on plots that occur infrequently and more weight on plots that occur frequently.

# custom window fn to get prop of surrounding cells matching focal value
# ?terra::focal
match_focal_cells_fn <- function(v, ...) {
  if(all(is.na(v))){ return(NA) }
  
  # center index of the window vector
  center_idx <- (length(v) + 1) / 2
  focal_val  <- v[center_idx]
  
  if(is.na(focal_val)){ return(NA) }
  
  # count how many cells in the window match the focal cell
  n_matches <- sum(v %in% focal_val, ...)
  prop_matches <- n_matches / length(v)

before we build the model we need to scale the x, y, and height data but we need to be sure to scale both the training and data to be predicted using the same scale so we use data on the same scale across both data. Centering and scaling the x, y, and height variables puts the center of the area of interest (weighted by number of trees) at the “zero” point and resolves the sign (i.e. +/-) conflicts of the coordinate system (i.e. UTMs) by making the signs represent relative direction (north vs south) rather than arbitrary coordinate origins. we also need to convert the tree species in the training data to factor from character data type.

  forcats::lvls_union(list(

While not specifically designed for evaluating the accuracy of a proposed prediction method, the vegan package provides utilities for comparing species assemblages using community ecology methods. Let’s use the vegan::vegdist() function to compute the Bray-Curtis index which can be used to quantify the compositional dissimilarity between two different samples. This index is bounded between 0 and 1, where 0 = same composition and 1 = maximally dissimilar (see here). For our purposes, dissimilarity quantifies the proportion of the total predicted trees that were assigned the incorrect species relative to the reference (i.e. field-measured) community profile.

Because Bray-Curtis is a dissimilarity measure and Schoener’s D (total overlap) index which we looked at above is a similarity measure, they can be interpreted as:

\[\textrm{Bray-Curtis}_{dissimilarity} \approx 1-\textrm{Schoener}_{similarity}\]

rf_model_vote_predictions <- function(mod_list, predict_df){
  # get model predictions for each model

          mod_list[[x]]

        dplyr::as_tibble() %>%
        dplyr::pull(1) %>%
        dplyr::as_tibble() %>%
        dplyr::rename(value=1) %>%
        dplyr::mutate(id=dplyr::row_number())

      dplyr::bind_rows()
  # predicted_temp %>% dplyr::glimpse()

    dplyr::ungroup() %>%
    dplyr::arrange(id) %>%
    dplyr::rename(predicted=value) %>% 
    dplyr::select(predicted)
  # return
  return(predicted_temp)

The overestimation of stand-level gross volume by 10.0% to 14.3% mirrors this trend, especially when trees aren’t (improperly) removed from the volume summation due to being classified as a non-timber species as in the random, proportional assignment.
